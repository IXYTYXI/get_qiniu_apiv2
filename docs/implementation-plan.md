# 独立直播采集项目实现计划

目标：上游 API → 回放下载 → FFmpeg 按小时输出 MP3 → 用户身份写飞书附件；历史弹幕独立分页写表。无妙记、无数据库。

已确认设计：复用上游接口协议，新仓库独立实现。按用户实际 Base：一场直播一行，音频切片放在同一附件格；四张分类弹幕表一条弹幕一行。源凭证仅从环境变量读取。飞书通过 lark-cli 用户身份调用，支持 CLI 自带的大文件上传。

- [x] 建立 HTTP 模拟测试：令牌刷新、分页、重复游标失败、业务错误。
- [x] 实现 api.py 和 config.py：只重试可恢复读取错误，分页上限与游标检查。
- [x] 建立 FFmpeg 集成测试：生成短视频，提音频、切片，ffprobe 验证分片和总时长。
- [x] 实现 media.py：流式下载、临时文件、音频片段校验、持久化媒体清单。
- [x] 建立飞书适配器测试：表结构检查、200 行批次、已有消息跳过、已有音频附件跳过、写失败不标成功。
- [x] 实现 feishu.py：只使用用户身份的 lark-cli base shortcuts；失败停止当前写入，重新运行先读远端查重。
- [x] 实现 pipeline.py / cli.py：按开播自然日或直播ID筛选，dry-run，仅弹幕/仅音频，逐场错误汇总，本地互斥锁。
- [x] 增加 README、配置模板、CI，执行全部测试与 CLI smoke test。
- [x] 审查 diff、凭证与排除文件，提交并同步 GitHub/GitLab 的项目分支。

验证不使用用户真实直播凭证，不写任何旧项目飞书表。真实联调需新项目专用 Base 与上游凭证。

审查修复：音频 SHA-256 指纹进入文件名与本地校验清单；源视频切片失败时移除程序视频缓存，以便重新下载。
